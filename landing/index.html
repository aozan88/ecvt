How it works

Five agents, each doing one job. Code holds the order and the state; the model decides only what needs judgement.

01 · ManagerPlans the run

Classifies the request, picks the stages, retries or stops.

→
02 · Domain intelModels the domain

Entities, rules and the gaps the spec leaves open.

→
03 · ScenariosWrites the tests

Seven categories, each runnable exactly as written.

→
05 · ExecutionRuns them

Through a plugin; races and replays really fire.

→
06 · EvaluationScores them

Deterministic rules first, an AI judge only where they can't decide.

What's inside

Domain-agnostic core; everything specific to a system lives in a plugin.

Plugins

rest_api for any HTTP API; wallet adds seven money rules — no negative balance, a replayed transfer moves money once, balances reconcile.

MCP scoring server

ecvt-eval exposes the rule engine as an MCP tool. Evaluation scores through it, and so can Claude Code or any MCP client.

Two reports

Business: a release recommendation and findings in plain words. Developer: failing checks, the judge's reasoning and a request-by-request repro.

n8n trigger

A webhook starts a run and answers with the result — from CI, a chat command or a schedule.

Gates and evals

Every agent has an eval set judged over repeated runs; a milestone closes only when its gate passes.

Ground truth stays out

The defect list is read in one place — the catch-rate report — and never by an agent.

Quick start

Python 3.11+ and an Anthropic API key in .env.

pip install -r requirements.txt
uvicorn app:app --app-dir examples/wallet-api --port 8000 &   # demo target

ecvt run --plugin wallet --report             # generate → execute → score → reports
ecvt run --manager --plugin wallet --report   # the same run, planned by the Manager
ecvt report artifacts                         # Dev + Business reports for a finished run
ecvt serve                                    # HTTP trigger for n8n

Reports land in the run directory as Markdown and HTML.
